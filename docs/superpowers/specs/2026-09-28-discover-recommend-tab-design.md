# 发现页"推荐"tab(个性电台 + 探索未知)设计

- 日期:2026-09-28
- 状态:待用户审阅
- 关联代码库:`lx-music-mobile/lx-music-mobile-master`(lx-music-mobile 定制版)

## 1. 背景与目标

发现页(Discover)目前只有"排行榜 / 歌单"两个 tab。目标:新增"推荐"tab,包含两个点击即播的电台模块:

- **个性电台**:基于用户本地行为数据(播放历史、收藏)构建个性化歌池,点击直接随机播放。
- **探索未知**:播放用户画像之外(补集)的音乐领域,帮助用户发现不常听的风格。

### 核心思路(无风格元数据的前提)

各音乐源接口不提供单曲风格/genre 字段。本设计不依赖风格元数据:

- **个性化**用"高频歌手 + 歌单共现"替代:播放历史/收藏统计出高频歌手;种子歌搜索到的歌单,其内其他歌视为口味相近内容(歌单本身是人类按风格整理好的聚类,歌单归属隐含风格)。
- **探索**用"画像补集"替代"陌生风格":已知领域 = 画像中出现过的全部歌手;探索池从歌单分类空间随机采样后,排除已知歌手的歌。分类仅作采样空间,不做分类级画像映射(各源歌单搜索结果不含分类字段,分类级映射不可行)。

## 2. 范围

**做**:

- 发现页新增"推荐"tab(与排行榜、歌单并列)
- 个性电台、探索未知两个模块,点击后构建歌池并通过试听机制直接播放
- 队列播完自动续批(个性电台)
- 新用户(无画像)与接口失败的降级路径

**不做**:

- 每日固定推荐列表(按天缓存的一份推荐歌单)
- 推荐/探索的播放历史记录、分类接触记录等新持久化
- 与发现页源选择器联动(见"源策略")
- 账号体系、服务端、任何数据上报

## 3. 源策略

构建歌池固定使用应用"歌单"设置的默认源(`songListSetting.source`),与发现页顶部源选择器**无关**。歌池内歌曲自带该源标识,播放时按歌曲自身的 source 解析链接。推荐模块 UI 不展示源选择。

## 4. 架构与模块划分

```
src/core/recommend/
  profile.ts    画像构建(纯函数):播放历史+收藏 → 歌手计数、种子歌
  radio.ts      个性电台歌池构建(调 musicSdk,拼装/去重/过滤/洗牌)
  explore.ts    探索歌池构建(分类采样 + 画像补集过滤)
src/screens/Home/Views/Recommend/index.tsx   推荐页 UI(两个大卡片)
src/screens/Home/Views/Discover/index.tsx    DISCOVER_TABS 增加 'recommend'
src/lang/zh-cn.json / zh-tw.json / en-us.json  新增文案(discover_recommend、卡片文案等)
```

播放复用现有试听机制:`addTempPlayList`(`src/core/player/tempPlayList.ts:10`)+ `playTempPlayList`(`src/core/player/player.ts:528`)。队列尾自动续批通过监听播放位置/播放结束事件追加新批次。

画像与歌池均**实时计算,不持久化**(输入规模 ≤ 100 条历史 + 收藏列表,计算开销可忽略)。

## 5. 画像(profile.ts)

输入:`getPlayHistory()`(上限 100 条,含完整 musicInfo)+ 收藏列表(love list)。

输出:

```
Profile {
  artists: { name: string, count: number }[]   // 历史+收藏中所有歌手,按 count 降序
  seedSongs: MusicInfo[]                        // 高频歌手的代表歌曲(取自历史/收藏原文)
}
```

规则:

- 歌手按 `singer` 字符串精确匹配计数(不做拆分归一化;多个歌手以原字符串为键)
- seedSongs:每位 top 歌手取其最近播放的 1 首;总量不超过 5
- 播放历史中 `isTempPlay` 的条目同样计入(真实播放行为)

## 6. 个性电台(radio.ts)

设当前源为 S(见"源策略"),点击卡片后:

1. **画像**:`profile.ts` 构建;取 artists 前 5 为 topArtists(count ≥ 2 者优先,不足 5 人则取实际数量,最少 1 人即开工)
2. **歌手拓展**(并行):对每位 topArtist——
   - kg 源:搜索接口按歌手名取歌曲(kg 有歌手接口 `musicSdk/kg/singer.js`,若实现成本低则优先走 `getSingerSongList`;歌手 id 需通过搜索歌曲详情获得,成本高则退化为与其它源一致的搜索方式,由实施计划定夺)
   - 其它源:`musicSearch` 搜索歌手名,取前 20 首
3. **共现拓展**:取 seedSongs 前 3 首,逐首 `songList.search(歌名)` 取前 2 个歌单,`getListDetail` 取歌单前 30 首
4. **合并**:歌名+歌手归一化去重;排除——黑名单、播放历史已含、收藏已含(按 source+songId 匹配,字段缺失时退化为歌名+歌手匹配)
5. **洗牌**后取 50 首入队:`addTempPlayList` → `playTempPlayList(0)`;50 首之外的剩余歌曲存为备选池(内存,不持久化)
6. **自动续批**:队列剩余 ≤ 2 首时优先从备选池取 30 首追加;备选池耗尽后用画像中未用过的歌手/种子歌重跑步骤 2-4,仍无新歌则停止续批

**降级**:画像为空(新用户)→ S 源热门排行榜前 50 洗牌开播;拓展全失败 → 同样退化为榜单内容。

## 7. 探索未知(explore.ts)

1. `getTags(S)` 拉取全部分类标签
2. 随机抽 1 个分类 → `getList(分类, 随机页)` → 取播放数最高的 1 个歌单 → `getListDetail` 取全部歌曲
3. **画像补集过滤**:排除黑名单 + 画像 `artists` 中所有歌手的歌(这是"补集"语义的落地:已知领域 = 画像歌手全集,而非分类级映射)
4. 洗牌后截取 50 首入队播放;卡片显示"正在探索:{分类名}"
5. 探索池用尽前(剩余 ≤ 2 首)自动换下一个随机分类续批

**降级**:

- `getTags` 失败 → 直接 `getList`(热门分类)取随机热门歌单
- 歌单详情失败或过滤后为空 → 重抽其它分类(最多 3 次)
- 连续失败 → 卡片显示错误 + 重试按钮

## 8. UI

- Discover 的 `DISCOVER_TABS` 增加 `'recommend'`,tab 文案 `discover_recommend`
- 推荐页纵向布局:上方"个性电台"大卡片,下方"探索未知"大卡片
- 卡片状态机:idle(标题+副文案)→ loading(构建歌池中)→ playing(副文案显示摘要,如"基于 张三、李四 等 5 位歌手" / "正在探索:摇滚")→ error(重试按钮)
- 点击卡片发起播放;再次点击卡片 = 换一批(重建歌池开播)
- 文案三语(zh-cn / zh-tw / en-us)

## 9. 错误处理

- 单个拓展请求失败(歌手搜索/歌单详情):跳过该来源,不阻塞整体构建
- 全部失败:进入降级路径;降级也失败 → 卡片 error 态 + 重试
- 续批失败:静默放弃本次续批,队列播完自然停止
- 构建过程设总超时(约 10s),超时走降级

## 10. 测试

- **单元测试**(沿用现有 `node --test` + `.mts` 模式,mock musicSdk):

  - radio.ts:去重、排除(黑名单/历史/收藏)、洗牌截取、降级触发
  - explore.ts:补集过滤、分类重抽逻辑
- **真机验证**(无线调试装 APK):点击开播、电台续批、探索分类轮转、黑名单过滤、断网降级

## 11. 非目标与后续
